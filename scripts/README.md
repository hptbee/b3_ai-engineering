# Scripts

Repository tooling, deterministic `/b3-ship`, `/b3-research-ship`, `/b3-review-loop`, and standalone command guard helpers, optional GitHub PR/merge adapters, context-budget measurement, and validation suites (`research/decisions/decision-010-autonomous-development.md`).

> **Native engine:** Deterministic commands run directly via the zero-dependency Rust `b3` executable (`target/release/b3.exe` / `b3`: `b3 guard <subcommand>`, `b3 pr <subcommand>`, `b3 context measure`, `b3 sync`, `b3 install <subcommand>`). The `scripts/*.{ps1,sh}` entrypoints automatically forward to `b3` (`B3_BIN` override or `target/release/b3*`).

### Merge Authorization Trust Boundary & Migration

- **Provider-neutral B3 Core + optional GitHub adapter:** `b3-guard merge-policy-check` operates cleanly in local Git repositories, non-GitHub remotes, and environments without `gh`. Policy is always read from canonical trunk authority (`<authority_ref>:.b3/research-policy.json` on `origin/HEAD` / `main` / `-AuthorityRef`), blocking unmerged branches or dirty worktrees from self-authorizing `auto_merge: authorized` or relaxing `protected_paths`. On remote-backed repositories without live provider verification, `ls-remote` checks remote authority/target freshness (`stale_remote_ref` → `MERGE_BLOCKED`) and emits `LOCAL_ELIGIBLE_ONLY` (exit `2`, non-authorizing for remote merge) rather than granting remote `MERGE_AUTHORIZED`. When `-PrNumber <N>` is passed, `b3-guard` delegates GitHub-specific PR/CI/target metadata queries to `scripts/b3-github-verify.{ps1,sh}` (`b3-gh-verify-v2`) and degrades honestly to `PROVIDER_UNAVAILABLE` (exit `2`, never `PASS`) when `gh`, Node, credentials, or GitHub APIs are unreachable.
- **Native hosting enforcement & CI evidence boundary:** GitHub-specific branch protection, ruleset evaluation, repository permission tiers, and reviewer association rules are enforced natively by the hosting provider on merge rather than simulated inside `b3-guard`. Locally, `MERGE_AUTHORIZED` (`mode=local|github`) requires `auto_merge: authorized` in trunk policy plus a fresh `LEDGER_GATE_PASS` `b3-review-ledger-v1` bound to exact `base_sha`/`head_sha` with `review_independence=INDEPENDENT`; when `require_ci: true`, caller `-CiStatus PASS` can block if negative (`FAIL`/`PENDING`) but never authorizes without an exact-commit `b3-verify-v1` `-ReceiptPath` (or receipt-backed ledger units) or independently observed provider CI (and `-RequireRemoteCi` forbids silently downgrading to local receipts).
- **Review-ledger migration (`review_independence`):** `review-ledger init` defaults to `review_independence=UNKNOWN` (failing closed on `HIGH`/`CRITICAL` and `merge-policy-check`). Pre-existing `b3-review-ledger-v1` files missing `review_independence=` fail closed as `LEDGER_CORRUPT` on `check` and migrate deterministically to `review_independence=UNKNOWN` via `b3-guard review-ledger -Action normalize -LedgerPath <path>`.

### Receipt migration (`b3-verify-v1`)

Legacy `b3-verify-v1` receipts generated before mode/type/gitlink fingerprinting retain the same schema and header fields, fail closed with `VERIFY_STALE` (exit `2` on `verify-check`, exit `1` `PRECOMMIT_FAIL` wrapping `VERIFY_STALE` on `precommit -RequireVerifyReceipt`), and auto-migrate cleanly when re-verified via `verify-run` (no manual receipt deletion or schema migration step required). Staged-vs-working-tree blob synchronization continues to be enforced by `precommit` while `verify-check` verifies effective working state plus index presence/mode divergence.
