# Subagent dispatch, adaptive scheduling & orchestration (on-demand)

Canonical orchestration, [clarification](clarification-gate.md), and [hook](hook-integration.md) contract inherited by all 14 B3 commands (`/b3-plan`, `/b3-implement`, `/b3-debug`, `/b3-research`, `/b3-audit`, `/b3-review`, `/b3-refactor`, `/b3-verify`, `/b3-review-loop`, `/b3-ship`, `/b3-research-ship`, `/b3-pr-{resolve,reply,comment}`). Load once; never copy into briefs.

- **Canonical roles & aliases:** Keep `agents/b3-*.md` stems/`name:` stable (`b3-reviewer`, `b3-fixer`, `b3-{security,architecture,performance}-reviewer`). Prefer lowercase kebab-case spawn aliases when supported: `b3-impl-<task-id-lower>`, `b3-review-u<NN>-p<K>`, `b3-fix-p<K>`, `b3-research-<slug>`, `b3-verify-<slug>`; never block on naming.
- **Session IDs & no nesting:** Store host agent IDs separately from aliases. Workers execute directly and **never** nest subagents (B3 subagents only, not product workers).

## Model preferences

- Read once per dispatch: `<project>/.b3/models.md`, then `~/.b3/models.md` (`B3_MODELS_PERSONAL`). Precedence: user > project > personal > `auto` across `planning`, `debugging`, `implementation`, `b3-reviewer`, `b3-fixer`, and specialists.
- **Single-task fast-path:** 1-unit `XS` + `inline` runs inline on `main` when `implementation` is unset/`auto` (or matches `main`); dispatch `b3-impl-<task-id-lower>` when model differs, size `>= S`, `notes`/`detailed`, or multi-unit. Never edit host settings or `agents/*.md` (`model: inherit`) or claim unverified switches.

## Continuous scheduling & safe integration contract

- **Critical-path ready ordering:** Rank ready tasks by (1) downstream tasks unlocked, (2) grounded long-running/high-complexity scope, and (3) risk/isolation cost. Run trivial 1-unit `XS` inline; never stall ready independent work behind artificial wave barriers.
- **Event-driven continuous dispatch:** Waves are initial/incremental dispatch batches, **not** completion barriers. Whenever an active worker exits, validate its result, update state, recompute ready tasks, and immediately run admission for `Active Workers + Newly Ready Candidates` (e.g., `A + E` start -> `A` finishes while `E` runs -> `B, C, D` immediately evaluate against active `E` and fill available slots without waiting for `E`).
- **`TASK_VERIFIED != DEPENDENCY_OUTPUT_AVAILABLE`:** Dependent `B` (`depends_on: [A]`) becomes ready **only** when `A` is verified **and** `A`'s output is available in `B`'s starting context:
  - `SHARED_READ_ONLY` / research: artifact written, validated (`evidence-check` if applicable), and recorded (`output_ready`).
  - `SHARED_DISJOINT_WRITES`: `A`'s scoped verification passed and files exist stably in the shared WT (`output_ready`). **Never `git commit` (advancing `HEAD`) in a shared WT while peer `SHARED_DISJOINT_WRITES` workers remain active**; pass `A`'s uncommitted verified files via `--verified-dirty-paths` until a commit-safe quiescent window.
  - `ISOLATED_WRITES`: `A` is **not** ready for dependents merely by passing inside `wt-a`; Parent must first integrate `A` into the integration branch (`integrated`) so `B` starts from integrated state.
- **Adaptive concurrency & lean packets:** Scale concurrency by independent work, context/CPU/memory/rate budgets, host limits, and throughput (no fixed `3`/`4` caps; `check-wave --partition` defaults to `available_parallelism` `4..=16`, explicit `--max-concurrency 1..64`; fall back to conservative `--max-concurrency` or `1` on `SINGLE_AGENT_LIMIT` if host limits unknown). Pass `<=25L` packets (`approach`/targets minus `## Inspected`, `files`/`read_only_deps`, 1L `context_hint:`, matched skill; no orchestrator docs). Reuse healthy MCPs (`context-routing.md`) optionally; reuse subsystem workers unless independence is needed (always fresh workers for reviews). Parent owns clarification, shared state, integration, commits, and PR mutations.

## 4 adaptive isolation modes (least-expensive-safe)

1. `SHARED_READ_ONLY`: concurrent research, discovery, analysis, verification, and review via `check-wave --partition` (`TaskId=none`/`[]` + `--wave-reads`) in the existing WT without temp files, extra WTs, or commits; detects RW conflicts against writers.
2. `SHARED_DISJOINT_WRITES`: concurrent writers in 1 WT **only** when: (a) `check-wave --partition` clears non-`.` disjoint writes with 0 RW/dirty/protected conflicts; (b) build/test/lint commands have no colliding side effects (caches, codegen, DBs, ports); (c) workers **never** stage, commit, checkout, merge, rebase, stash, or mutate Git; (d) Parent runs pre-integration `mechanical-check` and post-integration `verify-run` + cross-unit review (`review-loop/strategy.md`). Escalate to `ISOLATED_WRITES`/`SEQUENTIAL` when OS isolation is needed.
3. `ISOLATED_WRITES`: separate `git worktree` per writer for high risk, broad/uncertain scope, side-effect collisions, separate commits, or strict attribution. Verify via `b3 guard check-worktree --repo-root <wt> --require-isolated --expected-root <parent> --expected-base-sha <sha> --peer-roots <other_wts>` (proving `linked=true` `isolated=true` non-nested roots; `worktree_identity_failed` → `SEQUENTIAL`).
4. `SEQUENTIAL`: fallback when parallel dispatch is unjustified/blocked (`single_ready_task`, `trivial_overhead`, `dependency_chain`, `shared_write_conflict`, `read_write_conflict`, `unsafe_shared_side_effects`, `dirty_scope_conflict`, `no_host_isolation`, `sequential_host_fallback`, `malformed_wave_output`, `worktree_identity_failed`, `bounded_concurrency`). Disclose reason code when independent work exists.

## Active-worker admission, ownership & incremental integration

- **Active-worker conflict & slot admission (`b3 guard check-wave`):** Run `b3 guard check-wave --partition --max-concurrency <N> --wave-specs <ready> [--wave-reads <ready_reads>] [--active-specs <running>] [--active-reads <running_reads>] [--verified-dirty-paths <verified_uncommitted>] [--protected-paths <csv>] [--ignore-dirty-paths <initial_dirty_paths>] [--check-dirty-scope] [--expected-base-sha <sha>]`:
  - Reject `.` root writer ownership; `--protected-paths` guards `.git/`, `.b3/`, ledgers/manifests, `evidence-index.md`, authority records, and `single_writer_paths` (rejecting symlink/junction aliases).
  - Act strictly on `admitted_tasks` (`wave|1|PARALLEL|agents=<N>|tasks=<csv>|...` or `wave|1|SEQUENTIAL|...`, bounded by `available_slots = max(0, max_concurrency - active_count)`), keep `deferred_tasks` queued until an active worker exits, and fail closed on duplicate active TaskIds (`WAVE_FAIL`), `UNEXPECTED_DIRTY` (`WAVE_BASE_MISMATCH`), or malformed output (`SEQUENTIAL` `malformed_wave_output` / `BLOCKED`).
- **Canonical `mechanical-check` ownership:** Pre-commit run `b3 guard mechanical-check --base-sha <sha> --allowed-paths <wave_owned> [--wave-specs <TaskId=owned;...>] [--worker-changes <TaskId=changed;...> | --worker-roots <TaskId=wt;...> [--worker-bases <TaskId=sha;...>]] [--protected-paths <csv>] [--dirty-digests <path=sha256|DELETED;...>] [--ignore-dirty-paths <initial_dirty_paths>] [--obsoletes <csv>]`:
  - `ownership_verification`: `UNVERIFIED_COMBINED_ONLY` (`exit 0`, ordinary `SHARED_DISJOINT_WRITES`; never claim per-worker proof), `CALLER_ATTRIBUTED` (`exit 0`, `--worker-changes`), `VERIFIED_PER_WORKER` (`exit 0`, `--worker-roots`), `PARTIAL_ATTRIBUTION` (`exit 2`, `missing_worker`), `VIOLATION` (`exit 2`, cross-worker/unowned/unattributed/phantom/content-mismatch/`stale_base_conflict`/`protected_violations`/`dirty_tamper`).
- **Safe incremental integration, partial failure & resume (`Cursor`, `Claude Code`, `Codex`, `Antigravity`):**
  - When `A` integrated/committed into Parent (`HEAD` -> `sha_A`) while isolated peer `E` (`wt-e`) remained untouched at `sha_0`, never silently rebase or mutate active `wt-e`; when `E` finishes, validate with `b3 guard mechanical-check --base-sha <sha_A> --worker-roots "E=<wt-e>" --worker-bases "E=<sha_0>"` (diffs `wt-e` from `sha_0` and fails closed with `E->stale_base_conflict` if `sha_0..sha_A` touched `E`'s scope).
  - On partial worker failure (`C` fails while `D` verifies and `E` runs), isolate `C` (`failed`/`blocked`), preserve `D`'s verified output and `E`'s active execution, and never run destructive `git reset` across peer work.
  - On resume/compaction, reconcile `progress.md` (`in_progress` + `impl_agent` + `task_base` + `integration`), never re-dispatch an already active TaskId, and re-run `check-freshness`/`verify-check` to invalidate only stale evidence.
  - Without parallel subagents or required isolation, degrade to `SEQUENTIAL` (`no_host_isolation`/`sequential_host_fallback`; `SINGLE_AGENT_LIMIT` blocks `PASS` on `HIGH`/`CRITICAL`; never report `PARALLEL`). Keep `progress.md`, `findings.md`, ledgers/manifests, authority pins, `review-ledger`, PR mutations, and `b3 guard precommit` single-writer.
- **Wave status (`last_wave:` / report — actual executed concurrency only):** `dispatch=PARALLEL agents=<actual_N> isolation=<SHARED_READ_ONLY|SHARED_DISJOINT_WRITES|ISOLATED_WRITES>` or `dispatch=SEQUENTIAL reason=<reason_code>`.
